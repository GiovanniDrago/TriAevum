# Beta.1b Release Qualification

Date: 2026-10-14. Scope: Windows x64 portable ZIP, Linux x86-64 AppImage and
Linux x86-64 Flatpak bundle (candidate r9).
Supported inputs: decrypted EUR and USA dumps, original and Rev 1, as for
[beta.1](v0.8.0-beta.1-qualification.md).

## Source and Package Boundaries

- Runtime/source freeze: `94421bac21c729b45e8a80fa3ecf6ee0d9b34633`
  (branch `release/0.8.0-beta.1b`). The release tag may also include this
  subsequent documentation-only record.
- All packages pass the allowlist/hash/source audit with no errors.
  Windows contains 85 catalogued files; Linux contains 542. The AppImage and
  the Flatpak carry the same audited Linux inventory, as in beta.1.
- Runtime and Forge are packaged separately from ROM-derived data. No ROM,
  `code.bin`, save, capture, SDK or TopScreen payload is distributed.
- Precompiled title module: a new translation, because the title module now
  starts a block at each TopScreen site (`29d0375`). Translated with the
  beta.1 inputs and PGO profile; the build at the release commit reused all
  257 objects of that translation (cache key `43cd908a…`), so its build
  source is the release commit itself.
  Windows `91f18fc498fa8a3a2fc5f0b3b0d1dbc6c889b0cba4642c0384fbeadea582860d`,
  Linux platform rebuild from the same 259 translated sources in the Steam
  Runtime 4 SDK `122d99685e9ba013d816abb80a2838eb0a1db8a7417ca92753667cffcb4b3409`.
  The runtime refuses a module without those block starts.
- DLSS module: Windows `triaevum_dlss.dll` `8ec337a5…`, Linux
  `libtriaevum_dlss.so` `84dcc345…`, each beside NVIDIA's runtime and licence.
- MXAO library: Windows `ee7f04b6…` (rebuilt), Linux `64b10155…` (as beta.1).

## Checks Performed

- Release tooling: 486 tests, 13 explicitly skipped, no failures.
- Developer-build verification of the START and pause changes (`cd12a88`):
  all eight pause/input unit suites; 34 issue-60 input timelines (early START
  closes, reopen gaps, touch closes, held and rapid START, B/START and tab
  combinations) with one completed transaction per edge and no faults;
  remembered Items/Gear/Map pages, a Save-page visit, START held across a
  close and from the title screen into gameplay, save and load while an open
  is queued, and the unchanged `--ui-profile oot3d` behaviour. START latency
  to the page background: +13/+14 host frames by input phase, against +14 in
  TopScreen 2.1.1 under Azahar.
- Clean-Windows script (`qualify_clean_windows.ps1`) on the final ZIP's
  contents, frozen Forge install worker, no SDK on PATH:

  | Input | Forge install | Boot | Guest draws | First-launch benchmark |
  | --- | --- | --- | --- | --- |
  | EUR (private dump) | 52.9 s | 1,200 frames, exit 0 | 42,637 | 53.5 FPS |
  | USA Rev 1 (No-Intro 1259) | 67.6 s | 1,200 frames, exit 0 | 43,009 | 53.4 FPS |

  These installs reused the device's driver pipeline cache, so they do not
  repeat beta.1's cold 200-second figure. The installed EUR package then ran
  the title-to-file-select timeline: 1,800 frames, file select reached, no
  START transaction on the title.
- Packaged Linux runtime (AppImage) on the Linux reference machine (KDE
  Wayland, GeForce RTX 4060): Forge install 226.9 s; two bounded boots of
  1,800 frames with the title-to-file-select timeline, 37,254 and 37,182
  guest draws, exit zero, no pending draws, file select captured.
- Flatpak on the same machine in an isolated user installation: install of
  the bundle 78.6 s, sandboxed Forge install 227.3 s, two boots of 1,800
  frames, 37,182 and 37,218 guest draws, exit zero, no pending draws, file
  select captured. Flatpak OSTree commit
  `2b9082cb22b7543a74f54d624c9b37558edd1680738c069c6d23f36b426bf7d0`.
  Linux frame rates (49–58 FPS) are not claimed: the reference machine's
  monitor was in DPMS off for part of the session.
- Two regressions were caught by the qualification of an earlier candidate
  (r7) and fixed before this one: START on the title screen was taken by the
  TopScreen pause routing, so the game never left the title (`a859730`), and
  the file select showed the pause edge strips that 2.1.1 does not draw in
  scene mode 5 (`94421ba`). Both followed from `29d0375` making the
  TopScreen sites reachable in release builds; beta.1 had neither.
- Forge: on one candidate install the TopScreen 2.1.1 texture download
  stopped at 16% with an empty error message; the repeated install
  downloaded normally. The download code is beta.1's; the empty message is
  a known limit of this release.

## Known Limits

As beta.1. Captures are functional checks, not pixel equivalence. The Forge
GUI was not driven interactively.
