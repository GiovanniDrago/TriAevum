# Beta.1b Release Qualification

Date: 2026-10-15. Scope: Windows x64 portable ZIP, Linux x86-64 AppImage and
Linux x86-64 Flatpak bundle (candidate r10).
Supported inputs: decrypted EUR and USA dumps, original and Rev 1, as for
[beta.1](v0.8.0-beta.1-qualification.md).

## Source and Package Boundaries

- Runtime/source freeze: `60d74207cb77a1f57ffd3bdc2eb0720803d62be9`
  (branch `release/0.8.0-beta.1b`). The release tag may also include this
  subsequent documentation-only record.
- All packages pass the allowlist/hash/source audit with no errors.
  Windows contains 86 catalogued files; Linux contains 576. The AppImage and
  the Flatpak carry the same audited Linux inventory, as in beta.1.
- Linux C++ runtime (#72): the package carries the Steam Runtime 4 SDK's
  `libstdc++.so.6` and `libgcc_s.so.1` in `lib/compat-cxx`, which AppRun
  puts on the library path only when the host's libstdc++ lacks the
  required GLIBCXX level. The Forge module finds the bundled libraries
  through `$ORIGIN` RUNPATHs. libdecor, libXtst, libfribidi, liblzma,
  libzstd, libcrypto and libz are bundled as well. Their Debian copyright
  files, the referenced common licences and a pointer to the Steam Runtime
  4.0.20260805.254769 source archive are in `LICENSES/linux`.
- Runtime and Forge are packaged separately from ROM-derived data. No ROM,
  `code.bin`, save, capture, SDK or TopScreen payload is distributed.
- Precompiled title module: a new translation relative to beta.1, because
  the title module now starts a block at each TopScreen site (`29d0375`).
  Translated with the beta.1 inputs and PGO profile; the build at the release
  commit reused all 257 objects of that translation (cache key `43cd908a…`),
  so its build source is the release commit itself. The binaries are
  identical to candidate r9's.
  Windows `91f18fc498fa8a3a2fc5f0b3b0d1dbc6c889b0cba4642c0384fbeadea582860d`,
  Linux platform rebuild from the same 259 translated sources in the Steam
  Runtime 4 SDK `122d99685e9ba013d816abb80a2838eb0a1db8a7417ca92753667cffcb4b3409`.
  The runtime refuses a module without those block starts.
- DLSS module: Windows `triaevum_dlss.dll` `8ec337a5…`, Linux
  `libtriaevum_dlss.so` `84dcc345…`, each beside NVIDIA's runtime and licence.
- MXAO library: Windows `ee7f04b6…` (rebuilt), Linux `64b10155…` (as beta.1).

## Checks Performed

- Release tooling: 499 tests, 13 explicitly skipped, no failures.
- Changes since candidate r9, each verified on the developer build:
  - Extended draw distance kept un-culled actors past the title's per-frame
    light arena (128 records), which overwrote the file-worker queue and
    hung or faulted scene loads and saves (#69, #74). The actor-visibility
    adapter now budgets extra actors against the live arena (`a556c0d`).
    Five real-time minutes in Hyrule Field at night with the option on
    peaked at 96 records per frame over more than ten scene transitions,
    against 157 records and a fault before the fix. Host requests the
    runtime cannot serve now reply or fault instead of parking a guest
    thread (`82bf5a2`).
  - Grass: the product defaults carry the maintainer's 22-rule profile,
    which covers Lon Lon Ranch (`5f0f023`). Configurations saved by an
    earlier version take these texture and mask rules once (settings
    schema 15) and keep every other grass setting (`ca693ae`). A beta.1
    configuration migrated from 6 to 22 rules with no other change.
  - Frame interpolation and motion vectors: one motion per actor, CMB
    transforms through one screw motion, texture scrolls blended the short
    way, motion history keyed by native instance, and DLSS orientation
    descriptors keyed by resource lifetime.
  - Vulkan graphics pipeline libraries follow one policy for game and
    Forge and default off on Intel anv (#72).
- Developer-build verification of the START and pause changes (`cd12a88`):
  all eight pause/input unit suites; 34 issue-60 input timelines (early START
  closes, reopen gaps, touch closes, held and rapid START, B/START and tab
  combinations) with one completed transaction per edge and no faults;
  remembered Items/Gear/Map pages, a Save-page visit, START held across a
  close and from the title screen into gameplay, save and load while an open
  is queued, and the unchanged `--ui-profile oot3d` behaviour. START latency
  to the page background: +13/+14 host frames by input phase, against +14 in
  TopScreen 2.1.1 under Azahar.
- Clean-Windows script (`qualify_clean_windows.ps1`) on the final ZIP's
  contents, frozen Forge install worker, no SDK on PATH:

  | Input | Forge install | Boot | Guest draws | First-launch benchmark |
  | --- | --- | --- | --- | --- |
  | EUR (private dump) | 69 s | 1,200 frames, exit 0 | 42,637 | 53.7 FPS |
  | USA Rev 1 (No-Intro 1259) | 70 s | 1,200 frames, exit 0 | 42,637 | 53.6 FPS |

  These installs reused the device's driver pipeline cache, so they do not
  repeat beta.1's cold 200-second figure. The installed EUR package then ran
  the title-to-file-select timeline: 1,800 frames, file select reached, no
  START transaction on the title. Both installed configurations are at
  settings schema 15 with the 22 grass rules.
- Packaged Linux runtime (AppImage) on the Linux reference machine (KDE
  Wayland, GeForce RTX 4060): Forge install 209.6 s; two bounded boots of
  1,800 frames with the title-to-file-select timeline, 69,438 and 69,366
  guest draws, exit zero, no pending draws, file select captured.
- Flatpak on the same machine in an isolated user installation: install of
  the bundle 81.1 s, sandboxed Forge install 210.2 s, two boots of 1,800
  frames, 69,474 and 69,366 guest draws, exit zero, no pending draws, file
  select captured. Flatpak OSTree commit
  `c9e8cc4847241bcf04dbfb593b2aa49f4983d2bc10edadc3845641081acade63`.
  Both installed configurations carry the 22 grass rules.
- The Linux machine's monitor was in DPMS off during those boots. The
  compositor then paces presentation at about 19 FPS, and the guest, which
  runs in real time, submits more draws over the longer run. With the
  display on, interleaved boots of the r10 and r9 AppImages gave 58.8 and
  58.7 FPS for r10 against 58.6 and 58.9 FPS for r9, with 37,002 to 37,218
  guest draws each, matching r9's qualification.
- Two regressions were caught by the qualification of candidate r7 and
  fixed before r9: START on the title screen was taken by the
  TopScreen pause routing, so the game never left the title (`a859730`), and
  the file select showed the pause edge strips that 2.1.1 does not draw in
  scene mode 5 (`94421ba`). Both followed from `29d0375` making the
  TopScreen sites reachable in release builds; beta.1 had neither.
- Forge: on one candidate install the TopScreen 2.1.1 texture download
  stopped at 16% with an empty error message; the repeated install
  downloaded normally. The download code is beta.1's; the empty message is
  a known limit of this release.

## Known Limits

As beta.1. Captures are functional checks, not pixel equivalence. The Forge
GUI was not driven interactively.
