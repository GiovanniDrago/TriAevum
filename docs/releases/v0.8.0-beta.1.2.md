# TriAevum v0.8.0-beta.1.2

## Your Reports, Our To-Do List

> **Still a beta.** One developer, two NVIDIA machines, one AMD machine since
> this version, and your reports. If something breaks (or works), please
> [open an issue](https://github.com/coccofresco/TriAevum/issues/new) with your
> GPU, driver version, operating system, the console output and
> `logs/oot3d_native_game.log` (Windows: next to `TriAevum.exe`; Linux: inside
> TriAevum's data folder, for the Flatpak under

Beta.1.2 is the answer to the reports that followed beta.1.1, plus the work on
grass, 4K and input lag that was waiting for a release to ride on. Windows and
Linux, as usual.

### Reported and fixed

- **Map floors** (#89): in dungeons, the D-pad and the circle pad change floor
  again on the pause map.
- **Modern lighting changes while A is held** (#91, #95, #99): with Roll Dash
  on, holding A to run made the lighting, the shadows and Navi's hat flicker to
  the "no scene" state. The dash hook had been clobbering the game's view of
  the current scene; it keeps it now, Navi enters the hat only while Link
  actually dashes, and the scene identity survives the whole run.
- **Won't launch from a long folder** (#92) and **crash on installation**
  (#103): the game and Forge kept their title files within Windows' path limit,
  so an installation under a deep folder (OneDrive, "Documents\Games\..." and
  friends) opens its files instead of failing. If your folder path is very
  long, it still works; if it is absurdly long, Forge says so.
- **Crash on the very final scene** (#104): the end credits asked the DSP to
  flush and invalidate its data cache, two commands the host had not
  implemented. They are served now; the credits roll to the end.
- **VRAM growing until it crashed** (#98): textures that no draw sampled for a
  while are released, the grass refuses buffers past its VRAM budget and frees
  them after the frame, and the texture-pack cache no longer keeps the previous
  pack. The budget is read through the Vulkan loader at run time, so the
  executable still starts on a loader older than Vulkan 1.1 (the `0xC0000139`
  reports of the first beta, #12 and #35, stay fixed).
- **Barinade** (#76), round two: the precompiled Enhanced shader library is
  recorded again on this exact runtime, on both machines, and the release
  refuses a library that does not match its own source. From an empty cache the
  fight still compiles **zero** shaders.
- **AMD** (#78, #84, #93): this is the first release qualified on an AMD GPU
  (Radeon, Mesa RADV, Linux). Forge installed from the ROM and the game booted
  to the file select with zero shader compiles. Windows AMD drivers remain
  untested by us; please keep the reports coming.

### Ocarina Reframed's file selection

The file select is now Ocarina Reframed's: Link stands beside the three files
on the upper screen, with the copy and erase confirmations, all drawn by typed
code at the game's own block boundaries. The title logo is drawn as a layer
over the resolved scene, and the file select has its own scene lighting
identity, so starting a new game and loading a save look the same.

### SingleScreen 3.1 and the HD interface

- **Sheikah Stone Visions** list on the upper screen (3.1), play, complete and
  cancel without losing the game (#83 asked for the 3.1 update; here it is).
- **HD interface by language**: Forge offers the HD UI texture pack for the
  language your ROM boots in, downloaded with your consent, and bundles the
  SingleScreen HD font. The SingleScreen 3.1 archive is preselected when you
  drop it beside Forge.
- **Vanilla+ Link** (optional): a local RomFS overlay in `mods/` remodels Link
  without touching the ROM.

### Grass, 4K and input lag

- **Grass that stays**: its placement and residency now live within a VRAM
  budget; when the budget is tight the visible grass is thinned evenly instead
  of vanishing by cluster order in one camera direction. Whole blades draw with
  early depth, as camera-facing ribbons by default, and two more surface rules
  find grass where the first ones missed it.
- **4K without an upscaler**: water reflections and ambient occlusion run at
  half resolution with a depth-aware upsample, which is where the 4K frame
  went. On an RTX 3060 at 3840×2160, Kokiri Forest goes from about 19 to 18 ms
  and Hyrule Field with the river from 26 to 18 ms per frame.
- **Input lag**: input is sampled after the previous frame ended and the
  presentation cadence was fixed; at 60 Hz with interpolation the time from
  button to screen goes from about 33 ms to 9 ms on the development PC.

### In-game menu

Esc (or R3) opens a settings menu in the game's own UI renderer, with a photo
mode tab and an aspect ratio picture. F1 stays for everything else.

### Windows package layout

The ZIP's root holds `TriAevumForge.exe`, `README.md` and `LICENSE`; Forge
puts `TriAevum.exe` at the root when it installs, with its DLLs in `runtime/`.
Launch the game from the root as before.

### Updating

Back up your saves first; it is still a beta.

- **Windows**: extract the ZIP to a new folder and run `TriAevumForge.exe`.
  To keep your progress, copy the `data\savedata` folder of your previous
  folder into the new one before starting the game.
- **Linux**: replace the AppImage, or install the new Flatpak bundle with the
  same `flatpak install --user` command; saves stay where they are.

Use your own decrypted EUR/USA `.3ds` or `.cci` dump (original or Rev 1);
Japanese, Korean and Taiwanese releases are not supported yet. The previous
notes: [beta.1.1](v0.8.0-beta.1.1.md), [beta.1c](v0.8.0-beta.1c.md),
[beta.1b](v0.8.0-beta.1b.md), [beta.1](v0.8.0-beta.1.md).
